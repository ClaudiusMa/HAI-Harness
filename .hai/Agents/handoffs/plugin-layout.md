## What changed

- **R1 layout** — `bin/hai-harness.mjs`: `init`/`update`/`migrate`/`doctor` take the project root and install into `.hai/` (`harnessDirectory`, `layoutOf`). A `--target` named `.hai` is refused (`assertProjectRoot`). human-sync resolves a project root to `.hai/` (`harnessRootFor`). The HAI-Harness source repository is never read as a root-layout install (package.json name check). The update checker defaults to its own harness folder, and `--disable`/`--enable` keep the other receipt fields.
- **R2 block** — `scaffold/AGENTS.md` is now the block body (449 words, 3 steps, 8 invariants). `refreshEntryBlock`/`findEntryBlock`: install creates or appends; update rewrites only between the markers; a removed block stays removed (receipt `block: true`); duplicate or unbalanced markers leave the file untouched; `doctor` reports a missing or malformed block (`entryBlockProblem`).
- **R3 ownership** — `scaffold/shipped-hashes.json` (38 paths, 195 hashes, from all of `main` history plus the working tree) is generated by `scripts/shipped-hashes.mjs`. `refreshHarness` replaces a core file only if it matches a shipped hash or the receipt hash; otherwise it is kept and reported. `--accept-upstream <path>` is repeatable. The receipt records core hashes. A retired `.hai/AGENTS.md` is removed when pristine and kept when edited. `doctor` lists edited core files.
- **R4 migrate** — `migrate [--dry-run]`, package only: refuses a dirty checkout or an existing `.hai/Agents`; uses `git mv -k` plus an on-disk move for ignored leftovers; replaces an unedited old entry file with just the block, otherwise appends the block; reports role-like files, unshipped skills, `node Agents/…` mentions and open lanes. A re-run is a no-op.
- **R5 custom roles** — `Agents/custom/{roles,skills}/README.md`; rules in the block (Role step), onboarding (role selection, trigger, Claudia read order, Custom roles read order, "Custom roles and skills" section, core-files-belong-to-harness rule) and `claudia.md` (trigger 9, Custom roles section, read-order step 8). `doctor` validates frontmatter, built-in name collisions, name/file mismatch and shipped-skill shadowing, and flags role-like files and unshipped skills left in core folders. `Agents/custom/roles` is traced; older packets stay valid until adopted (`laterTracedPaths`).
- **R6 docs** — README (install, safe updates, custom roles and skills, migration, developing), CONTRIBUTING, `.hai/README.md`, root `AGENTS.md` repository note, `hai-meta` (root target). Outer `project_context.md` updated by Claudia.

## Independent review (Julius, deep tier, read-only) and fixes

No path deleted user content. The confirmed findings, all fixed by Claudia, with regression tests (suite now **42/42**):

1. Ignore rules anchored at old paths (`/Human/private/`) stopped matching after the move, so approve would have committed private files. `migrate` now lists ignored paths before moving, refuses the real run when the `.hai/` path would no longer be ignored, and reports this in the dry run.
2. A half-finished migrate was read as complete. `layoutOf` now returns `partial`; `update`, `init` and `doctor` stop with a resume hint, and `migrate` moves only the pieces still at the root, refusing when a piece exists in both places.
3. With no receipt (gitignored, fresh clone), `update` re-added a removed block. It now adds the block only when a pre-block signal is present (an old receipt without `block`, or a retired `.hai/AGENTS.md`); `migrate` always adopts.
4. CRLF checkouts made every core file look edited. Hashing folds CRLF to LF in the CLI and the generator.
5. Open lanes keep human-sync packets under the old root scope: migrate's open-lane report now says to capture or hand off their drafts first (no re-keying).
6. Wording: misspellings still count for custom role names; a custom role never writes beyond its `writes` level, however assigned; migrate always flags a kept, edited `AGENTS.md` for review of old paths.
7. Edge cases: a BOM before the block is kept (no duplicate block); a capitalized built-in filename (`Claudia.md`) is flagged. Not changed: marker pairs inside code fences (documented examples) are still counted, which is safe because the file is then left untouched; the generator covers only HEAD ancestry.
